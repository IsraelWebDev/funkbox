# funk v3.1 "projects": drop files in, get an ad (implementation plan)

**Audience:** an implementer model. The same rules apply as `PLAN-v3-reel.md`, plus `PLAN.md`
sections 1, 5 and 7. Don't modify v1/v2 files. v3 files may change only where this plan says so,
and all existing tests must stay green.

## 0. Goal

Today the user must hand-place files under `inputs/`, hand-write `copy.json`, and hand-write a
`*.reel.json`. v3.1 makes this:

1. The user drops anything (product photo, logo, music, video clips, scene images) into
   **`C:\dev\funkbox\inbox\`**, or tells Claude a folder path.
2. Claude calls `new_project` → `ingest` → `brand_from_assets` → `propose_copy` (the user approves)
   → `auto_reel` → storyboard → render.

**The exactness guarantee must survive.** Claude may now *draft* copy, but only lines the user
approved can reach pixels or audio, and the approved deck is hash-locked.

## 1. Project layout (`reel/project.py`)

```
funkbox/projects/<slug>/
  project.json        # name, created, status, brand, copy_lock (sha256 of copy.json), notes
  product/            # product.png (alpha cut-out) + original(s)
  brand/              # logo.png, fonts/*.ttf|otf (optional)
  shots/              # scene stills (jpg/png/webp)
  clips/              # video clips (mp4/mov/webm)
  music/              # audio (mp3/wav/m4a/ogg/flac)
  copy.draft.json     # proposals (Claude may write)
  copy.json           # APPROVED copy (written ONLY by approve_copy after user approval)
  <slug>.reel.json    # generated by auto_reel, editable
  out/                # renders for this project
```
- `slug` matches `^[a-z0-9][a-z0-9-]{0,40}$`.
- `projects/` is added to the allowed path roots: set `FUNK_INPUTS`-style fencing, via a
  backwards-compatible extra root in funkgl's `allowed_roots` (env `FUNK_PROJECTS`, default
  `<funkbox>/projects`). Record this hook in the report.
- `inbox/` is created on first run. The `inbox` and `projects` folders and generated media are
  git-ignored.

## 2. Ingest (`ingest(project, source=None, move=True)`)

`source` defaults to `inbox/`. It may also be any folder or file path the user names. External
paths are **copied**, never moved, and are read-only otherwise. Classification:

| rule (first match wins) | destination |
|---|---|
| extension in audio set | `music/` |
| extension in video set | `clips/` |
| `.ttf/.otf` | `brand/fonts/` |
| filename contains `logo` (case-insensitive) or SVG | `brand/` (SVG → rasterise is out of scope: report "convert to PNG") |
| filename contains `product`/`bottle`/`pack`, OR the image has a real alpha channel, OR its border is near-uniform (≥ 92% of a 4%-wide border band within ΔE < 12 of the median border colour) **and** it's the only such image | product candidate |
| other images | `shots/` |

- **Product:** the best candidate (the filename hint beats alpha, and alpha beats a uniform
  border) gets its original kept in `product/original.*`. Then `product/product.png` is made:
  use the existing alpha if there is one, else `reel_cli cutout` logic. Report a
  **cut-out quality score**: the fraction of alpha that is cleanly 0/255 versus semi-transparent,
  plus whether the subject touches the image edge. Under the threshold, the tool says so and
  suggests the GIMP route.
- If there are several product candidates, don't guess. Return them and ask Claude to call
  `set_product(project, file)`.
- Duplicates (same sha256) are skipped. Unsupported files are listed and left in place.
- Images are EXIF-transposed. Huge images are downscaled to ≤ 2400 px on the long side. The
  original is kept in `shots/_orig/`.
- Returns a manifest: counts per type, the product decision, warnings, and a contact sheet
  PNG of everything ingested (thumbnails with their destination labels).

## 3. Brand (`brand_from_assets(project)`)

- **Palette:** k-means (k=6, numpy, seeded) over the product cut-out's opaque pixels, plus the
  logo if present. Pick:
  - `primary`: the most saturated cluster with ≥ 4% share;
  - `secondary`: the darkest cluster;
  - `text`: `#ffffff` or `#111111`, whichever has the better WCAG contrast on `primary`.
    Contrast must be ≥ 4.5, otherwise darken or lighten `primary` until it is, and note
    that you did.
- **Fonts:** user fonts in `brand/fonts/` win. Otherwise use the bundled Oswald and DM Serif
  Display.
- Writes `project.json.brand` and returns a swatch PNG. The user can override any value with
  `set_brand(project, primary=?, secondary=?, text=?, font_caption=?, font_display=?)`.

## 4. Copy: draft → approve → lock

- `propose_copy(project, lines: dict[id -> {text, say?}], pronounce?: dict)` writes
  `copy.draft.json`. It validates:
  - ids match `^[a-z][a-z0-9_]{0,30}$`;
  - each text is ≤ 90 chars;
  - every line fits the caption style at minimum size (reuse the v3 fit check).

  It returns a **numbered, exact listing** of every line (text and say). The tool result must
  instruct the agent to show the listing to the user verbatim and ask for approval.
- `approve_copy(project, draft_sha256)` copies the draft to `copy.json` and records `copy_lock`
  (the sha256 of the written file), the approval time and the method in `project.json`.
  Approval paths:
  1. **MCP elicitation, preferred.** The server calls the client's elicitation (mcp 2.x
     `Elicit`, or `ctx.elicit` in 1.x) with the exact listing and Approve / Reject options. The
     user clicks in the client UI, so approval doesn't depend on the agent. Method:
     `elicitation`.
  2. **Fallback** when the client doesn't support elicitation (catch the error or capability
     check). Require the argument `user_confirmed_in_chat: true`. Method: `chat`. The tool
     description must say: "only set this after the user explicitly approved the exact
     listing in this conversation."
  - `draft_sha256` must match the current draft. This stops approving a draft that changed
    after the user saw it.
- **Lock enforcement (v3 change):**
  - `render` and `validate` for a project reel verify that `sha256(copy.json) ==
    project.json.copy_lock`. On a mismatch they fail: "copy.json changed since approval; run
    propose_copy/approve_copy again."
  - Hand edits by the user are allowed through `reel_cli.py approve-copy <project>`, a CLI
    path the user runs themselves. It shows the listing, asks y/N on stdin and re-locks.
- `copy_diff(project)` shows the draft-vs-approved diff, line by line.
- The rule from v3 is unchanged: shots reference copy **by id only**. There is still no tool
  that writes `copy.json` directly.

## 5. Auto reel (`auto_reel(project, length_s=20, style="red-box", pace="fast", cta_ids=None, music=None)`)

Builds `<slug>.reel.json` deterministically (seeded by the slug):

- **Order:** hook (the first copy line) → body lines → end card (the copy ids whose names
  start with `end_`, plus `url` if present; `cta_ids` overrides).
- **Shots:** cycle through `shots/` and `clips/`. Use clips for at most 40% of shots, so
  stills with motion dominate. If there are fewer than 4 visual assets, fill with funk2
  recipes using brand colours (a palette built from the brand) and **say so**.
- **Product appears** in every other shot, plus all hook and CTA shots.
  - Placement alternates between bottom-centre, right-third and left-third.
  - **Caption/product collision avoidance (new, also a v3 validator rule):** caption and
    product boxes must not overlap by more than 8% of the caption area. When they would,
    move the caption anchor (top ↔ bottom). If both anchors collide, shrink the product to
    0.85× once, then error.
- **Motion:** parallax on stills (Ken Burns when depth isn't available). Alternate push and
  orbit. `pace=fast` uses ~1.3 s shots with snap-to-beats, `calm` uses ~2.2 s with
  crossfades.
- **Reveals:** the hook uses typewriter, body lines alternate words and typewriter, and the
  end card's headline uses typewriter.
- **Voiceover:** VO is on if a voice model is installed and the copy has lines; music from
  `music/` is used if present.
- Duration: fit the shot count and durations to `length_s ± 2 s` (the end card is fixed at
  4 s).
- Returns the reel JSON, the validate report and the storyboard PNG in one result.

## 6. MCP and CLI surface

`reel_mcp.py` gains these tools, with the same `_safe` pattern:
- `new_project(name)`
- `list_projects()`
- `ingest(project, source?)`
- `set_product(project, file)`
- `brand_from_assets(project)`
- `set_brand(...)`
- `propose_copy(...)`
- `approve_copy(...)`
- `copy_diff(project)`
- `auto_reel(...)`
- `project_render(project, draft=True)`

Existing tools accept `project=` as an alternative to a raw reel dict. The CLI has the same
verbs. Update the server `instructions` to describe the flow in four sentences.

Also add a Windows shortcut helper, `reel_cli.py make-shortcuts`, which creates
desktop shortcuts **"funk inbox"** (opens the inbox folder) and **"funk projects"**. The user
runs it once; the agent may also run it, since it only creates links.

## 7. Milestones (commit `v3.1 P<n>: …`)

- **P1, project + ingest.**
  **Accept:** the tests check:
  - classification of a synthetic mixed folder (mp3/wav made with ffmpeg sine, an mp4 made
    from frames, a white-background product jpg, an alpha product png, a "logo.png" and
    3 scene images);
  - duplicate skipping;
  - an external folder is copied, not moved;
  - the ambiguous-product path returns candidates;
  - the cut-out score is reported.
- **P2, brand.**
  **Accept:** a product with a known red label → `primary` within ΔE < 10 of that red. The
  text colour contrast is ≥ 4.5.
- **P3, copy draft/approve/lock.**
  **Accept:**
  - elicitation approval in the stdio test client (supply an elicitation callback that
    accepts, and one that rejects);
  - the fallback requires `user_confirmed_in_chat`;
  - a stale `draft_sha256` is rejected;
  - editing `copy.json` after approval makes `validate` fail with the lock message;
  - the CLI `approve-copy` re-locks, testing stdin "y".
- **P4, auto_reel + collision rule.**
  **Accept:**
  - the synthetic project produces a valid reel of 20±2 s;
  - the product appears in ≥ 50% of shots;
  - no caption/product overlap > 8% (computed from layout boxes);
  - the hook is first and the CTA is in the end card;
  - the funk2 filler is used and reported when there are < 4 visuals.
- **P5, MCP + shortcuts + docs.**
  - The MCP stdio test runs the whole flow end to end on synthetic assets through to a draft
    render, and the text audit passes.
  - Update the README with a "Make an ad in 5 steps" section and write `BUILD_REPORT-v3.1.md`.

Definition of done: P1–P5 and the full suite green.

## 8. Packaging for agent self-install (P6) and publication prep (P7)

The repo will be published **publicly** as `IsraelWebDev/funkbox` under the **MIT** licence. The
publish itself (squash and push) is done by the supervising agent, not you. Your job is to make the
tree publishable and self-installable.

### P6: self-install
- **`pyproject.toml`** for uv/pip, non-packaged (`[tool.uv] package = false`):
  - `requires-python >=3.10`;
  - dependencies = the current `requirements.txt`;
  - optional groups `reel` (= requirements-reel.txt) and `dev` (pytest).

  Keep the `requirements*.txt` files in sync; a test checks they match.
- **`install.py`**: one cross-platform installer, stdlib only, idempotent. Agents and humans
  run it the same way: `python install.py [--with reel,fastsd,gimp] [--register desktop|code|none] [--shortcuts] [--dry-run] [--yes]`.
  1. Create `.venv` with `uv` if present, else `python -m venv`, and install deps
     (+ extras).
  2. `--with reel`: run `reel_cli.py setup-models` and print the model licences.
  3. `--with fastsd`: `git clone --depth 1 https://github.com/rupeshs/fastsdcpu` into
     `vendor/fastsdcpu` (git-ignored, never committed), then:
     - create its venv the way its install script does: python 3.11 via uv, torch CPU
       wheel, then its requirements;
     - pin `pydantic>=2.11,<2.12`;
     - copy `studio/start_local_mcp.py` into it.
  4. `--with gimp`: `git clone --depth 1 https://github.com/maorcc/gimp-mcp` into
     `vendor/gimp-mcp`, run `uv sync` there, and locate GIMP 3. If GIMP is missing, print the
     official download URL and the winget id `GIMP.GIMP.3`. **Never install GIMP silently.**
  5. `--register desktop`: merge the MCP entries into Claude Desktop's config.
     - Paths: `%APPDATA%\Claude\claude_desktop_config.json` on Windows,
       `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS,
       `~/.config/Claude/claude_desktop_config.json` on Linux.
     - Back up first with a timestamp. Only add or update the funkbox keys
       (`funk`, `funk2`, `reel`, `studio`, `gimp`); never touch other servers.
     - Print a warning that Claude Desktop must be fully quit while this runs, because it can
       overwrite the file.

     `--register code` writes a project `.mcp.json` and prints the `claude mcp add` lines.
  6. `--shortcuts`: on Windows, create "GIMP + MCP", "funk inbox" and "funk projects" on
     the desktop. On macOS and Linux, print the equivalent commands.
  7. End with a self-test that renders a tiny funk2 loop, prints a summary of what was
     installed and registered, and prints next steps.

  `--dry-run` prints every action without doing it. Without `--yes` it asks before
  changing Claude configs.
- **Remove hardcoded machine paths.** `C:\dev\fastsdcpu`, `C:\dev\gimp-mcp`, user-name paths
  and the like must resolve, in order, from:
  1. env vars (`FASTSD_DIR`, `GIMP_MCP_DIR`, `GIMP_EXE`);
  2. `funkbox.toml` in the repo root (optional, written by `install.py`);
  3. defaults under `vendor/`.

  `studio/GIMP-MCP.cmd` becomes a template that `install.py --shortcuts` renders with real
  paths into a git-ignored location.
- **Claude Code plugin** (agents install with
  `/plugin marketplace add IsraelWebDev/funkbox` then `/plugin install funkbox`):
  - `.claude-plugin/marketplace.json` and `.claude-plugin/plugin.json`;
  - `skills/funk-studio/SKILL.md`, copied from `docs/skill/SKILL.md`, which the supervising
    agent will provide; use a placeholder until then;
  - `.mcp.json` at the plugin root whose servers launch via
    `uv run --project ${CLAUDE_PLUGIN_ROOT} python ${CLAUDE_PLUGIN_ROOT}/<server>.py`, so uv
    builds the venv on first launch. Document that `uv` is required and that heavy extras
    still need `install.py`.

  Check the current plugin/marketplace JSON schema in Claude Code's docs. If you can't fetch
  them, keep the files minimal and note it.
- **`AGENTS.md`**: exact, copy-pasteable install steps for an AI agent on Windows, macOS and
  Linux:
  - prerequisites (python ≥ 3.10, git, uv recommended);
  - the `install.py` invocations;
  - how to verify;
  - how to uninstall: delete the folder, then remove the five keys from the config. Add
    `install.py --unregister`, which does that removal with a backup.
- **CI:** `.github/workflows/tests.yml` runs on ubuntu-latest with Python 3.12. It installs
  `libegl1 libgl1-mesa-dri ffmpeg`, runs `pip install -r requirements.txt pytest`, then
  `FUNK_GL_BACKEND=egl pytest -q`. Tests needing models or Piper must skip cleanly when those
  are absent; they mostly already do.

**Accept:**
- `python install.py --dry-run --with reel,fastsd,gimp --register desktop --shortcuts` prints a
  correct plan on Linux.
- A test runs `install.py --register desktop` against a temp config containing an unrelated
  server: that server survives, the funkbox keys are added and the backup exists. Then
  `--unregister` removes only the funkbox keys.
- The plugin JSON files parse. `uv run --project . python funk2_mcp.py` starts and answers
  `list_tools` (test it if `uv` is available, otherwise skip).
